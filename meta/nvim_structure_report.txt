KEY DIRECTORY PURPOSES:
=======================

1. CORE (6 files)
   - Foundation configuration that must load first
   - Global paths, OS detection, plugin manager setup
   - Main entry point for core initialization
   - Settings that affect the entire system

2. KEYMAP (8 files)
   - All keybindings organized by category
   - Helpers for creating consistent key mappings
   - User can override keybindings in user/keymap/

3. MODULES/PLUGINS (5 files)
   - Plugin specifications organized by category
   - Defines which plugins are loaded and their conditions
   - Links to actual plugin configurations

4. MODULES/CONFIGS (81 files)
   - Individual plugin configuration files
   - Organized into 5 categories: completion, editor, lang, tool, ui
   - Each plugin has its own dedicated config file
   - Language-specific configs in lang/
   - Debugger configs in tool/dap/

5. MODULES/UTILS (4 files)
   - Shared utility functions
   - Palette management and highlighting
   - Icon definitions
   - Plugin loading helpers

6. USER (25 files)
   - User-specific customizations
   - Can override default configs without modifying core files
   - Mirrors core structure for easy override
   - Used for personal plugins and settings

NOTES FOR DOCUMENTATION:
=========================

1. The configuration uses a modular architecture with lazy loading for performance
2. User customizations should go in lua/user/ to maintain clean git history
3. Plugin configs use a helper system (load_plugin) for easy user overrides
4. Most config files include Chinese comments explaining plugin purpose
5. Settings can be extended via user/settings.lua without modifying core files
6. Keybindings are chainable (builder pattern) for readable configuration
7. The system supports multiple platforms (Linux, macOS, Windows, WSL)
